# v2026.522.0

> Release date: 2026-05-22
> Status: Draft

## Summary

- Adds the StacyOS federation demo substrate inside the sealed `packages/federation`
  workspace package.
- Proves the local N=2 flow: create a signed Knowledge Object on install A,
  federate to install B with consent, read on B with provenance, revoke on A,
  and deny B's next read.
- Adds repeatable demo verification with real Stacy DB and real two-install
  local server smoke tests.

## Operator Notes

- Run the federation demo gate before presenting or merging release candidates:

```bash
STACY_FEDERATION_DEMO_REPEAT=3 pnpm --filter @arpanstacy/stacy-federation demo:repeat
```

- The real smoke tests start embedded Postgres and local Stacy servers on
  loopback ports. Sandboxed environments may need permission to bind localhost.
- StacyVM is not part of the critical path for this release and was not modified.

## Changes

### Added

- Sealed `@arpanstacy/stacy-federation` package with identity, signed KO,
  consent, revocation, sync, receipts, and harness modules.
- Ed25519 install identities and canonical signed Knowledge Objects.
- `stacy brain create`, `stacy brain show`, `stacy share`, and `stacy revoke`
  federation command wiring.
- `/api/federation` receive endpoint and `/api/federation/revocations` lookup
  endpoint.
- Read-time consent and revocation enforcement on the consumer install.
- Append-only federation receipts for create, sign, share, receive, store, read,
  deny, and revoke events.
- Two-install harness plus acceptance, adversarial, real DB, and real server
  smoke coverage.
- Phase 5 reliability scripts:
  - `preflight`
  - `test:acceptance`
  - `smoke:db`
  - `smoke:server`
  - `demo:check`
  - `demo:repeat`
- Federation demo runbook and phase gate notes.

### Changed

- CLI and server package wiring now import the federation package.
- Server app mounts the package-owned federation routes.
- Vitest workspace config includes `packages/federation`.
- `AGENTS.md` includes federation scope and harness rules.

## Rollback

- Remove the CLI and server federation wiring.
- Remove the `@arpanstacy/stacy-federation` workspace dependency from the CLI
  and server packages.

- No StacyVM rollback is required.

## Known Limitations

- This is an investor-demo federation substrate, not production federation
  hardening.
- Revocation is proven through read-time consumer enforcement at N=2 scale.
- Real smoke tests require localhost process and port access.
