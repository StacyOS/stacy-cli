# v2026.522.0

> Release date: 2026-05-22
> Status: Draft

## Summary

- Adds the StacyOS federation demo substrate inside the sealed `packages/federation`
  workspace package.
- Proves the local N=2 flow: create a signed Knowledge Object on install A,
  federate to install B with consent, read on B with provenance, revoke on A,
  and deny B's next read.
- Adds repeatable demo verification with real Stacy DB and real two-install
  local server smoke tests.
- Adds a public demo path where a real CSV task becomes a signed dashboard KO,
  is shared by contact name, revoked, and denied on B's next read.
- Adds an adapter-command public demo mode while keeping deterministic dashboard
  generation as the reliable offline default.
- Adds signed contact-card export/import so public demo peer setup is verified
  instead of raw manual contact entry.
- Adds federation transport replay hardening with signed message nonces and a
  60-second signed timestamp window.

## Operator Notes

- Clean checkout public demo:

```bash
pnpm install
pnpm --filter @arpanstacy/stacy-federation preflight
STACY_FEDERATION_PUBLIC_DEMO_REPEAT=3 pnpm --filter @arpanstacy/stacy-federation demo:public:repeat
```

- Run the federation demo gate before presenting or merging release candidates:

```bash
STACY_FEDERATION_DEMO_REPEAT=3 pnpm --filter @arpanstacy/stacy-federation demo:repeat
```

- Run the public demo gate before external presentations:

```bash
STACY_FEDERATION_PUBLIC_DEMO_REPEAT=3 pnpm --filter @arpanstacy/stacy-federation demo:public:repeat
```

- The real smoke tests start embedded Postgres and local Stacy servers on
  loopback ports. Sandboxed environments may need permission to bind localhost.
- StacyVM is not part of the critical path for this release and was not modified.

## Changes

### Added

- Sealed `@arpanstacy/stacy-federation` package with identity, signed KO,
  consent, revocation, sync, receipts, and harness modules.
- Ed25519 install identities and canonical signed Knowledge Objects.
- `stacy brain create`, `stacy brain show`, `stacy share`, and `stacy revoke`
  federation command wiring.
- `/api/federation` receive endpoint and `/api/federation/revocations` lookup
  endpoint.
- Read-time consent and revocation enforcement on the consumer install.
- Append-only federation receipts for create, sign, share, receive, store, read,
  deny, and revoke events.
- Tamper-evident per-KO receipt hash chains plus `stacy receipts verify --ko <ko_id>`.
- Signed federation message nonces and replay-window checks before B stores
  inbound KO/grant state.
- Two-install harness plus acceptance, adversarial, real DB, and real server
  smoke coverage.
- Phase 5 reliability scripts:
  - `preflight`
  - `test:acceptance`
  - `smoke:db`
  - `smoke:server`
  - `demo:check`
  - `demo:repeat`
- Federation demo runbook and phase gate notes.
- Public demo fixture and scripts:
  - `demo/acme-q2-revenue.csv`
  - `demo:public`
  - `demo:public:adapter-smoke`
  - `demo:public:repeat`
- Minimal federation contact book and CLI commands:
  - `stacy contacts add`
  - `stacy contacts list`
  - `stacy contacts show`
  - `stacy contacts export`
  - `stacy contacts import`
- Receipt summary command:
  - `stacy receipts list --ko <ko_id>`
  - `stacy receipts verify --ko <ko_id>`
- Public task KO creation through `stacy run "<task>" --input <file>`.
- Optional dashboard schema support through
  `stacy run "<task>" --input <file> --schema <schema.json>`.

### Changed

- CLI and server package wiring now import the federation package.
- Server app mounts the package-owned federation routes.
- Vitest workspace config includes `packages/federation`.
- `AGENTS.md` includes federation scope and harness rules.
- `stacy run` keeps existing server-start behavior when called without a task,
  and creates a signed public-demo KO when called with a task and `--input`.
- CSV dashboard generation can use explicit schema JSON for arbitrary column
  names, while no-schema mode infers widgets from numeric columns.
- `demo:public` honors `STACY_PUBLIC_DEMO_ADAPTER` and
  `STACY_PUBLIC_DEMO_ADAPTER_ARGS` for adapter-backed task generation.
- `stacy share --with-contact <name>` can use a contact imported from a signed
  contact card; explicit `--revocation-url` remains the producer's lookup URL
  for revocable shares.
- Inbound federation receive now rejects stale or replayed signed messages before
  persistence.

## Rollback

- Remove the CLI and server federation wiring.
- Remove the `@arpanstacy/stacy-federation` workspace dependency from the CLI
  and server packages.
- Remove `packages/federation` from the Vitest workspace config.
- No StacyVM rollback is required.

## Known Limitations

- This is an investor-demo federation substrate, not production federation
  hardening.
- Revocation is proven through read-time consumer enforcement at N=2 scale.
- Real smoke tests require localhost process and port access.
