# v2026.505.0

> Release date: 2026-05-05
> Status: Ready

## Summary

- Public-release polish cut from the current Stacy `main` branch.
- Adds the final user-owned local Codex/Claude connection workflow in the UI,
  so users connect their own local accounts instead of relying on bundled
  operator credentials.
- Hardens first-run local adapter authentication, issue liveness recovery, and
  end-to-end QA coverage before the public announcement.

## Operator Notes

- Run the upgrade preflight before changing the instance:

```bash
pnpm stacy upgrade:check --strict
```

- Create a fresh database backup before deploying:

```bash
pnpm stacy db:backup
```

- For Docker/self-hosted instances, stop the app before applying a restore:

```bash
docker compose -f docker/docker-compose.quickstart.yml down
pnpm stacy db:restore --latest --dry-run
pnpm stacy db:restore --latest --yes
docker compose -f docker/docker-compose.quickstart.yml up -d
```

## Changes

### Added

- Local adapter connection panel for Codex CLI and Claude Code accounts.
- Guided new-agent launch workflow that explains local account ownership,
  preflight checks, risk controls, and adapter readiness from the UI.
- Todo app and complex app E2E smoke profiles that create real browser-tested
  artifacts through Stacy.
- Dev-runner environment helper that creates an ephemeral local adapter JWT
  secret for local development when no persistent secret is configured.

### Changed

- The new-agent screen now uses a Stacy-specific operator launch flow rather
  than the inherited dashboard-style form layout.
- Onboarding and agent configuration surfaces now show local account connection
  status, auth remediation, and retest actions for Codex and Claude adapters.
- Codex local adapter remote execution tests now match the safer default CLI
  invocation flags used by the runtime.

### Fixed

- Local adapters now fail clearly when agent API authentication cannot be
  configured instead of silently falling back to unauthenticated board access.
- Claude 401/auth failures are surfaced as adapter authentication problems so
  the UI can guide the user to connect their own Claude account.
- Issue graph liveness traversal now uses an iterative walk, preventing stack
  overflow on very deep blocked-task chains.
- The todo E2E acceptance criteria now require visible checkbox controls, which
  catches incomplete task app output earlier.

## Rollback

- Restore the previous image/package version.
- Restore the latest known-good database backup if migrations or data changes need reversal.
- Re-run `pnpm stacy upgrade:check` after rollback.

## Known Limitations

- The exact `npx stacy onboard` vanity package remains blocked because
  `stacy` is already owned on npm. The public install path is
  `npx stacy-cli onboard`.
- A real successful Claude run requires the operator to be logged in through
  their own local Claude Code account. Stacy now guides that connection in the
  UI and classifies unauthenticated Claude runs clearly.
