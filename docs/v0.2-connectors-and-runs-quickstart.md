# StacyOS v0.2 Quickstart: Connectors + AI Runs

The v0.2 alpha adds two things on top of the [v0.1 local Knowledge Object
surface](v0.1-local-kos-quickstart.md): **connectors** that pull external data
(GitHub first) into signed Knowledge Objects, and **AI runs** that take those
KOs as context and produce a new signed `agent_output` KO. Everything is still
local-only — nothing leaves your install unless you explicitly acknowledge
egress.

A Knowledge Object (KO) is Ed25519-signed by your install identity and addressed
by its content hash. Ingestion and runs reuse those same primitives, so every
object you create here is independently verifiable.

## 0. Prerequisites

```bash
pnpm install
```

All commands run through the `stacy` CLI. In a fresh checkout use
`pnpm --filter @arpanstacy/stacy exec tsx src/index.ts <args>`; a published
install exposes it directly as `stacy <args>`.

You also need a GitHub OAuth app client id (set `STACY_GITHUB_CLIENT_ID` or pass
`--client-id`). For real AI runs you need `ANTHROPIC_API_KEY` and an adapter
command; for offline runs use the built-in `deterministic` adapter.

## 1. Connect GitHub

`stacy connect` uses the OAuth **device-code flow** — no redirect URL ceremony.

```bash
stacy connect github
```

```
Connecting to GitHub...
→ Visit https://github.com/login/device and enter code: ABCD-1234
→ Waiting for authorization...
✓ Connected as @octocat
✓ Token stored (encrypted, local)
✓ Scopes granted: repo
```

The token is stored encrypted at rest (AES-256-GCM) under your instance's
`secrets/` directory — never in plaintext config. Restrict to one org with
`--org <org>`.

## 2. See connector status

```bash
stacy connectors list
stacy connectors status
```

`list` shows every available connector and whether it is connected. `status`
makes a live call to confirm the stored token still works and reports the
account and granted scopes.

## 3. Ingest GitHub data as Knowledge Objects

```bash
stacy ingest github --repo octocat/hello-world --pulls --state open
```

Stacy fetches and normalizes the objects first, then shows a confirmation
summary before writing anything:

```
Stacy will ingest:
  Connector:    github
  Repo:         octocat/hello-world
  Object kinds: github_pull_request
  Filter:       state=open
  Estimated:    2 object(s)
  Storage:      local only
  Sharing:      off by default
Continue? [y/N]
```

Confirm (or pass `--yes` for scripting). Each object becomes a signed KO with
connector provenance, and `ingest` + `normalize` receipts are appended next to
the usual `create` + `sign`. Add `--issues` for issues, `--label`, or
`--since 7d` to narrow the set.

Verify any ingested object:

```bash
stacy brain verify <ko_id>
```

## 4. Run an AI task over those KOs

Select the input KOs with repeated `--use` flags. The output is a new signed KO
of kind `agent_output` whose provenance lists every input id.

```bash
stacy run "Create a release risk report" \
  --use ko_github_pr_231 \
  --use ko_github_pr_232 \
  --ack-egress \
  --model claude-sonnet-4-5
```

```
Egress acknowledgement: ✓ (--ack-egress provided)
Adapter: anthropic
Model: claude-sonnet-4-5
Input KOs: 2 (ko_github_pr_231, ko_github_pr_232)
✓ Output schema valid (agent_output)
✓ KO created: ko_b8c8fac…
Content hash: sha256:…
Receipts: run, sign, create
```

Stacy verifies **every input KO before the model call**, requires `--ack-egress`
for any adapter that leaves the install, and signs the result. The new KO's
`provenance.inputKoIds` points back at the exact inputs.

### Offline / reproducible runs

For tests, demos, or air-gapped use, the `deterministic` adapter produces a
templated synthesis with no network and no egress acknowledgement:

```bash
stacy run "Summarize these PRs" --use ko_github_pr_231 --adapter deterministic
```

## 5. Inspect the run output and receipts

```bash
stacy brain show <agent_output_ko_id>
stacy receipts list --ko <agent_output_ko_id>
stacy receipts verify
```

The `run` receipt records the adapter, model, and the input KO ids; `verify`
proves the chain has not been altered.

## What you just proved

- External data (GitHub PRs/issues) becomes signed, verifiable KOs with
  recorded connector provenance.
- AI runs are gated: inputs are verified first, egress is explicit, and the
  output is a signed KO that points at its inputs.
- The whole pipeline stays local and tamper-evident — the receipt chain covers
  ingest, normalize, and run alongside create and sign.

See [Connectors](concepts/connectors.md) and [AI runs](concepts/ai-runs.md) for
the underlying model, and the [GitHub connector reference](connectors/github.md)
for scopes and filters.
