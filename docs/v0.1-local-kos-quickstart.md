# StacyOS v0.1 Quickstart: Local Knowledge Objects

This is the alpha (v0.1) happy path. It uses only your local install — no
federation, no network. You create a signed Knowledge Object (KO), list it,
inspect it, move it between machines as a file, and confirm every step is
cryptographically verifiable.

A Knowledge Object is a piece of content (JSON, a dashboard, a note) that is
Ed25519-signed by your install identity and addressed by its content hash. If
the bytes change, verification fails.

## 0. Prerequisites

```bash
pnpm install
```

All commands below are run through the `stacy` CLI. In a fresh checkout you can
run it with `pnpm --filter @arpanstacy/stacy exec tsx src/index.ts <args>`; a
published install exposes it directly as `stacy <args>`.

## 1. See your install identity

Your install identity is the keypair that signs every KO you create. It is
generated automatically on first use.

```bash
stacy identity show
```

You will see your `install_…` id, the derived person/worker ids, the public
key, and where the identity file lives on disk. The private key is never
printed.

Make a private backup of the keypair (keep this file safe — it contains the
private key):

```bash
stacy identity backup --out ~/stacy-identity.backup.json
```

## 2. Create a local Knowledge Object

```bash
stacy brain create \
  --content-json '{"title":"Hello StacyOS","note":"my first KO"}' \
  --content-type application/json \
  --json
```

The output includes the new KO id and its `sha256:…` content hash. The KO is
signed by your install identity and stored in your local Brain.

## 3. List what you have stored

```bash
stacy brain list
```

This prints a table of locally stored KOs (id, content type, source, created
time). Add `--json` for machine-readable output, or filter with
`--content-type`, `--source local|federated`, and `--limit`.

## 4. Inspect and verify a Knowledge Object

```bash
stacy brain show <ko_id>
```

`show` reads the stored bytes, re-verifies the signature and content hash, and
renders the content (dashboards get a compact dashboard view). If the stored
bytes had been tampered with, this command would refuse to display them.

## 5. Move a Knowledge Object as a file

Export a KO to a portable, self-describing file:

```bash
stacy brain export <ko_id> --out hello.stacy-ko.json
```

The file is an envelope: `{ "kind": "stacy_knowledge_object_export",
"schemaVersion": 1, "ko": { … } }`. It contains the signature and signer, so it
is independently verifiable.

Import it — on the same machine or another one:

```bash
stacy brain import hello.stacy-ko.json
```

Import re-verifies the signature and content hash **before** storing. A tampered
file is rejected with `Cannot import invalid Knowledge Object`. By default the
imported KO is recorded with source `federated`; pass `--source local` to keep
it as a local object.

## 6. Confirm the receipt chain

Every operation appends to a tamper-evident receipt log. Verify it end to end:

```bash
stacy receipts list
stacy receipts verify
```

A valid chain proves the recorded history has not been altered.

## What you just proved

- Every KO is signed by your install identity and addressed by content hash.
- Reads (`show`), imports, and the receipt log all re-verify — tampering is
  detected, not trusted.
- KOs are portable: `export` / `import` move signed objects between installs as
  plain files, with verification preserved.

This is the full v0.1 local surface. Federation (sharing KOs with other installs
under per-object consent) builds on these same primitives via `stacy share`,
`stacy contacts`, and `stacy revoke`.
