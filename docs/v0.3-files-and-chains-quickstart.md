# StacyOS v0.3 Quickstart: Local Files + Run Chains

The v0.3 alpha closes the **credential-free loop**. On top of the
[v0.2 connectors + AI runs](v0.2-connectors-and-runs-quickstart.md) layer it adds:

- **`brain create --file` / `--dir`** — turn local text/markdown/json files into
  signed Knowledge Objects with **no connector and no credentials**.
- **`run --chain`** — compose several runs, where a later step consumes an
  earlier step's `agent_output` KO.

Together these let you run the whole ingest → run → synthesize loop **offline**,
with zero external setup, using the built-in `deterministic` adapter.

A Knowledge Object (KO) is Ed25519-signed by your install identity and addressed
by its content hash, so every object below is independently verifiable.

## 0. Prerequisites

```bash
pnpm install
```

Commands run through the `stacy` CLI. In a fresh checkout use
`pnpm --filter @arpanstacy/stacy exec tsx src/index.ts <args>`; a published
install exposes `stacy <args>` directly. You need a Postgres connection (set
`STACY_FEDERATION_DB_URL`/`DATABASE_URL`, pass `--db-url`, or use the embedded
Postgres from `stacy init`). **No API key or OAuth app is required for this
quickstart.**

## 1. Create KOs from local files (no credentials)

A single file:

```bash
stacy brain create --file ./notes.md
```

The file is wrapped in a `{ kind: "document", source, mediaType, text }`
envelope and signed. The `source` is a cwd-relative path (a bare filename if the
file is outside cwd), so absolute paths never leak into a KO you might later
share or export. `.json` files are parsed into a structured `data` body.

A whole directory, one KO per file:

```bash
stacy brain create --dir ./docs --ext md,txt
# or with a glob:
stacy brain create --dir . --glob 'docs/**/*.md'
```

Directory mode shows a confirmation summary before writing (`--yes` to skip). It
skips dotfiles, `node_modules`, `.git`, and symlinks; binary and oversized files
(default 1 MiB, `--max-bytes` to change) are skipped with a warning instead of
aborting the batch.

List what you created:

```bash
stacy brain list
```

## 2. Run over them — offline

The `deterministic` adapter needs no network and no egress acknowledgement:

```bash
stacy brain create --file ./docs/pr-231.md --json   # note the KO id
stacy run "Summarize the release risk" --use <ko_id> --adapter deterministic
```

This produces a new signed `agent_output` KO whose provenance lists the input.

## 3. Chain runs together

A chain is a JSON file with an ordered `steps[]` array. A later step references
an earlier step's output with `@<stepId>`:

```jsonc
// chain.json
{
  "steps": [
    { "id": "per_doc",   "task": "Summarize each document", "use": ["<ko_a>", "<ko_b>"] },
    { "id": "synthesis", "task": "Synthesize one report",   "use": ["@per_doc"] }
  ]
}
```

```bash
stacy run --chain ./chain.json --adapter deterministic
```

```text
per_doc   use: [ko_a, ko_b] ──► ko_out1
synthesis use: [@per_doc]   ──► ko_final   (@per_doc resolves to ko_out1)
```

The spec is validated and every `@ref` resolved before anything runs, so a bad
reference fails immediately. Re-running an identical chain is fully cached
(zero adapter calls). A step failure aborts the chain and names the failed step;
KOs produced by earlier steps remain durable.

## 4. Verify the lineage

```bash
stacy brain show <ko_final>          # provenance.inputKoIds = [per_doc output]
stacy receipts list --ko <ko_final>  # create, sign, run
```

Provenance is **one-hop**: the synthesis KO points at the `per_doc` output,
which points at the original file KOs. Walking those edges reconstructs the full
lineage — nothing is flattened or duplicated.
